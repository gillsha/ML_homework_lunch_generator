# Задание: Random Lunch Generator

Создай полностью рабочее статическое веб-приложение, которое случайно выбирает идею для ланча. Все требования перечислены ниже; дополнительный контекст или предыдущая переписка не нужны.

## Формат приложения

- Весь HTML, CSS и JavaScript размести в одном файле `week1/index.html`: стили внутри `<style>`, логику внутри `<script>`.
- Используй обычный JavaScript без фреймворков, сборки, backend и обращений к ИИ. Приложение должно открываться непосредственно как локальный HTML-файл и работать на GitHub Pages.
- Единственная внешняя зависимость — Font Awesome **Free 6.4.0**, подключённый так:

  ```html
  <link rel="stylesheet" href="https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css">
  ```

- Для загрузки CSS и шрифта с CDN требуется интернет. Не заменяй библиотеку, её версию или иконки на emoji, изображения либо платные Pro-иконки.
- Укажи `lang="en"`, кодировку UTF-8, viewport для мобильных устройств и заголовок страницы `Random Lunch Menu Generator`.

## Интерфейс

Сделай компактную адаптивную страницу: розовый градиент фона, белая карточка по центру с закруглёнными углами и тенью, коралловые акценты. Максимальная ширина карточки — 500 px. На экране шириной 320 px элементы должны помещаться без горизонтальной прокрутки; перенос текста допустим.

Внутри карточки размести:

1. Заголовок `Random Lunch Generator` с иконкой `fas fa-utensils`.
2. Описание `Struggling to decide what to eat? Let us choose for you with just one click!`.
3. Светлый блок результата: крупная иконка и название блюда. Начальная разметка может содержать `fas fa-question` и `What's for lunch?`; после инициализации сразу начинается автоматический выбор.
4. Настоящую HTML-кнопку `Generate Lunch!` с иконкой `fas fa-random` и идентификатором `generateBtn`. Кнопка должна работать мышью и с клавиатуры.
5. Подпись `Click the button again if you can't decide!`.

Во время ожидания показывай в блоке результата `fas fa-spinner fa-spin` и текст `Thinking...`.

## Список блюд и точные классы иконок

Используй ровно эти 12 блюд в указанном порядке. Название и иконку храни вместе в одном объекте массива, чтобы они всегда соответствовали друг другу.

| Блюдо | Полный CSS-класс иконки |
|---|---|
| Pizza | `fas fa-pizza-slice` |
| Sushi | `fas fa-fish` |
| Burger | `fas fa-hamburger` |
| Salad | `fas fa-leaf` |
| Tacos | `fas fa-hotdog` |
| Ramen | `fas fa-bowl-food` |
| Sandwich | `fas fa-bread-slice` |
| Pasta | `fas fa-plate-wheat` |
| Curry | `fas fa-mortar-pestle` |
| Steak | `fas fa-bacon` |
| Soup | `fas fa-bowl-food` |
| BBQ | `fas fa-fire` |

Это согласованные условные обозначения: хот-дог представляет Tacos, бекон — Steak, тарелка с колосьями — Pasta, миска с едой — Ramen и Soup. Точного сходства с блюдом не требуется; повторное использование значка допустимо. Не переименовывай блюда в соответствии с этими изображениями и не подбирай другие иконки самостоятельно.

Все классы должны работать именно в бесплатном solid-наборе версии 6.4.0. Не придумывай названия по аналогии с блюдами: `fa-bowl-hot`, `fa-pasta` и `fa-bowl` в подключённом наборе не работают. Для проверки доступности используй метаданные версии 6.4.0: https://github.com/FortAwesome/Font-Awesome/blob/6.4.0/metadata/icons.json — и фактическую отрисовку в браузере с указанным CDN.

## Случайный выбор и блокировка кнопки

1. После готовности DOM зарегистрируй обработчик кнопки один раз и сразу запусти одну автоматическую генерацию. Первый результат не должен требовать клика.
2. Каждая принятая генерация независимо выбирает один из 12 элементов с одинаковой вероятностью, например через `Math.floor(Math.random() * lunchMenu.length)`. Одно и то же блюдо может выпадать несколько раз подряд; не исключай предыдущий результат.
3. Одновременно может выполняться только одна генерация. В самом начале функции проверь, не идёт ли уже ожидание; если идёт, немедленно выйди без нового выбора и таймера.
4. При принятии генерации синхронно установи кнопке настоящее свойство `disabled`. Одного CSS-класса или `aria-disabled` недостаточно. Состояние `disabled` можно использовать и как признак выполняющейся генерации.
5. Убери класс предыдущей анимации, выбери блюдо и покажи спиннер с `Thinking...`.
6. Через 500 мс обнови название и иконку выбранного блюда, запусти анимацию появления и снова сделай кнопку доступной. Используй один `setTimeout` на принятую генерацию.
7. Дополнительные нажатия во время ожидания игнорируются: не ставятся в очередь, не перезапускают задержку и не отменяют текущий выбор. Это относится и к ожиданию первого автоматического результата.
8. Недоступная кнопка должна заметно отличаться: например, иметь меньшую непрозрачность, курсор ожидания и не иметь тени. Hover- и active-эффекты применяй только к доступной кнопке.

## Анимация

- При показе результата используй `fadeIn` длительностью 500 мс: прозрачность от 0 до 1 и смещение по вертикали от 10 px до 0, с сохранением конечного состояния.
- В начале каждой принятой генерации снимай класс `fade-in`, а при показе результата добавляй его ровно один раз. Анимация должна запускаться заново даже при повторном выпадении того же блюда.
- Не допускай нескольких отложенных обновлений, которые последовательно меняют результат и добавляют уже установленный класс анимации.
- Кнопку разблокируй при показе результата, не дожидаясь окончания анимации. Если пользователь сразу начинает следующую генерацию, прерывание предыдущей анимации допустимо.

## Обязательные проверки

Проверь готовый файл в браузере. Для перебора блюд разрешено временно управлять `Math.random()` только в тестовой сессии; в приложении должен остаться настоящий случайный выбор.

1. **Первый запуск:** без клика появляется `Thinking...`, кнопка недоступна; примерно через 500 мс появляются блюдо и иконка, а кнопка становится доступной. Попытки нажать её во время начального ожидания не создают дополнительных результатов.
2. **Все 12 блюд:** последовательно вызови каждый вариант. Проверь точное название, согласованный CSS-класс и видимый символ иконки. Убедись, что CSS и шрифт Font Awesome загружены, а `::before` содержит ожидаемый символ. Одного наличия элемента `<i>` недостаточно.
3. **Быстрые нажатия:** нажми кнопку и повтори попытки через 100 и 200 мс, в том числе с клавиатуры. Должен появиться только один результат примерно через 500 мс после первого принятого нажатия, без последующих самопроизвольных смен.
4. **Повторная генерация:** после разблокировки следующий клик снова запускает цикл ожидания и показывает результат. Проверь несколько циклов подряд и не менее двух одинаковых результатов подряд.
5. **Анимация:** проверь первый результат, последующие результаты и повтор того же блюда. Каждый раз должна начинаться новая анимация появления. Также проверь новый клик до окончания предыдущей анимации: следующий цикл должен отработать корректно.
6. **Интерфейс:** проверь визуальное состояние недоступной кнопки, отсутствие у неё hover-эффекта, работу доступной кнопки по Enter и Space, а также отсутствие горизонтального переполнения на ширинах 320 и 1280 px.
7. **Ошибки:** проверь консоль JavaScript и загрузку ресурсов. Если CDN недоступен, отдельно сообщи об этом, не путай сетевой сбой с отсутствующим классом иконки.
